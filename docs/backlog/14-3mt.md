# 3MT

M8 dedicated postgraduate pathway, followed by separately gated M9 finals. This is not an abstract presentation-format option. The competition name does not authorize importing another organization's eligibility, time, slide, judging or affiliation rules. All issues below are planned.

<a id="bl-tmt-01"></a>

## BL-TMT-01 — Add a separately gated postgraduate draft

- **Source IDs:** TMT-01, TMT-02, SCP-03, LOC-02.
- **Status:** Planned; live opening blocked by 3MT configuration.
- **Purpose:** A prospective postgraduate presenter can use a distinct pathway without altering an abstract or attendance record.
- **Scope:** Dedicated draft identity; title, study/project narrative, presenter, affiliation and configured declarations; typed unset eligibility/participation limits; save/resume with visible errors and version checks.
- **Exclusions:** Treating 3MT as oral/poster format, imported external competition rules/affiliation, invented eligibility/evidence/limits, automatic conference admission.
- **Dependencies:** BL-FND-01; verified participant identity; BL-SEC-01; [DR-CFG-06](DECISION_REQUIRED.md#dr-cfg-06).
- **Roles:** Participant presenter; authorized 3MT administrator; 3MT lead owns settings.
- **States/transitions:** Dedicated editable draft can be saved/resumed; finalization remains closed while required 3MT settings are unset.
- **Data touched:** Owner-scoped 3MT draft, English narrative, presenter/affiliation, approved declarations and configuration version.
- **Acceptance criteria:** Draft is separate from abstract/registration records; missing eligibility/limit configuration does not default to unrestricted live entry; stale draft edits cannot overwrite acknowledged newer data.
- **English/Arabic:** Participant/admin labels/help/errors bilingual and Arabic RTL; scientific narrative English/LTR; official names may retain script.
- **Accessibility:** Labelled fields, accessible autosave/conflict status, error summary, keyboard/zoom and language switch without data loss.
- **Security/RLS:** Own-draft/edition checks, server schema validation, no mass assignment of approval/review state; data minimization follows approved purposes.
- **Audit/email:** Configuration changes audited; no autosave emails or external data transmission; safe diagnostics exclude narratives.
- **Automated tests:** Cross-owner denial, locale state preservation, stale edit, unset configuration gate and separation from abstract/registration records.
- **Manual UAT:** Save a synthetic 3MT draft in Arabic UI; reload, switch languages and confirm no invented rules appear.
- **Release gate:** REL-04 3MT stage and production privacy approval.
- **Owner type:** Full-stack engineer with 3MT/privacy lead.
- **TBD blocked:** Live entry yes, CFG-06/CFG-09; gated synthetic draft no.

## BL-TMT-02 — Finalize configured 3MT applications and private files

- **Source IDs:** TMT-01, TMT-02, TIM-01, TIM-02, SEC-03, ERR-02.
- **Status:** Planned.
- **Purpose:** An eligible presenter receives one immutable submitted application under approved 3MT-specific requirements.
- **Scope:** Server validation of approved eligibility/limits/declarations/file list; private upload policy; explicit preview and idempotent finalization; snapshot/reference and durable receipt; independent 3MT deadlines.
- **Exclusions:** Abstract 300-word/file defaults copied without approval, guessed slide/time limits, real production collection before approval, public scientific files.
- **Dependencies:** BL-TMT-01; private-file/durable-email foundations; [DR-CFG-06](DECISION_REQUIRED.md#dr-cfg-06).
- **Roles:** Verified Participant presenter; authorized 3MT administrator validates; restricted upload worker scans.
- **States/transitions:** Valid draft becomes a finalized immutable 3MT application before its server cutoff; incomplete/late/invalid action preserves recoverable draft with accurate status.
- **Data touched:** Application snapshot, eligibility evidence where approved, private attachments/versions, submission timestamp, idempotency key and outbox event.
- **Acceptance criteria:** Required stage configuration must exist before live finalization; retry creates one application; uploaded source is retained under approved history policy; quarantine prevents file access while status is visible.
- **English/Arabic:** Bilingual participant validation/receipt; scientific content English/LTR; all receipt emails English with locale-aware link.
- **Accessibility:** Accessible file alternatives/progress, keyboard preview/submit, explicit deadline timezone and focused correction summary.
- **Security/RLS:** Verified owner and approved stage/window checked server-side; file type/purpose/signature/size/scan controls; deny snapshot tampering and unrelated access.
- **Audit/email:** Audit finalization and consequential replacement; one English receipt via durable outbox; queueing is not represented as delivery.
- **Automated tests:** Unconfigured stage, limit validation under synthetic settings, upload spoofing/quarantine, deadline boundary, duplicate submit and owner mismatch.
- **Manual UAT:** Submit under labelled synthetic configuration, retry after response loss and inspect snapshot/private-file access.
- **Release gate:** REL-04 approved 3MT eligibility/form/files/limits/deadlines; REL-06 transactional/file evidence.
- **Owner type:** Full-stack/security engineer with 3MT lead.
- **TBD blocked:** Live finalization yes, CFG-06; schema/idempotency and synthetic upload tests no.

## BL-TMT-03 — Review and publish 3MT qualification outcomes independently

- **Source IDs:** TMT-01, TMT-02, ROL-04, REV-01, REV-07, AT-12.
- **Status:** Planned.
- **Purpose:** Assigned 3MT reviewers assess sanitized work and applicants receive only authorized qualification outcomes.
- **Scope:** 3MT-specific versioned review settings; sanitized packet; assignment/conflict/draft/score/lock flow; configured qualification stages; separate prepared decision and explicit publication with dashboard/outbox.
- **Exclusions:** Hackathon two-reviewer or research one-to-five defaults assumed for 3MT, invented scale/quorum/qualification stages, applicant identity in pre-event review, automatic threshold publication.
- **Dependencies:** BL-TMT-02; BL-REV-02 and BL-REV-05 shared security/publication patterns; approved 3MT rubric/stages.
- **Roles:** Assigned 3MT Reviewer; authorized 3MT administrator/publisher; Participant sees own published outcome.
- **States/transitions:** Administratively ready version receives configured assignments; completed assessment contributes under approved rules; prepared outcome remains hidden until explicit release.
- **Data touched:** Sanitized packet, assignment/rubric versions, human scores/conflicts, qualification decision snapshot, publication/outbox.
- **Acceptance criteria:** Missing stage/judge/rubric configuration blocks live review; reviewer cannot retrieve identities or peer status; stale-version results cannot silently qualify revised work; duplicate release produces one event.
- **English/Arabic:** Reviewer assessment English-only; participant/non-review administration bilingual; written scientific content English/LTR; English outcome email.
- **Accessibility:** Keyboard scoring and conflict declaration, semantic rubric, accessible decision preview and applicant fallback when email fails.
- **Security/RLS:** Assignment/track/version/MFA checks; separate publish grant; direct prepared-outcome and cross-participant requests denied.
- **Audit/email:** Audit assignments, review amendments, overrides and publication; no applicant email before publication; English deduplicated notifications.
- **Automated tests:** Identity canaries, self/conflict/unassigned denial, incomplete quorum under approved-test policy, stale scores, prepared-data leaks and duplicate publish.
- **Manual UAT:** Review synthetic 3MT as its own track, prepare a result, verify applicant cannot see it until authorized publication.
- **Release gate:** REL-04 approved 3MT qualification/review settings and REL-06 anonymity/publication evidence.
- **Owner type:** Full-stack engineer with 3MT/scientific lead and security QA.
- **TBD blocked:** Live review/qualification yes, CFG-06; reusable gated review/publication infrastructure no.

## BL-TMT-04 — Receive final 3MT material through an authorized request

- **Source IDs:** TMT-01, TMT-02, SEC-03, TIM-02, REL-04.
- **Status:** Planned; live final collection closed.
- **Purpose:** A qualified presenter can supply the approved final deliverable without assuming another competition's file rules.
- **Scope:** Authorized final-material request with approved format/count/window; private scanned upload, immutable replacement versions and explicit completion status; requested-presenter access.
- **Exclusions:** Invented duration/slide/file limits, judging, awards/certificates, public files, external affiliation claims.
- **Dependencies:** BL-TMT-03; shared private-upload foundation; [DR-CFG-06](DECISION_REQUIRED.md#dr-cfg-06).
- **Roles:** Requested qualified Participant; authorized 3MT administrator; assigned final judges receive only approved necessary material in the later judging slice.
- **States/transitions:** Authorized request opens final upload until server cutoff; completed material records its version and security-processing state separately from qualification; replacement preserves earlier versions.
- **Data touched:** Request, final private objects/snapshots, deliverable configuration, completion timestamp and lock/replacement history.
- **Acceptance criteria:** Missing final file configuration keeps collection closed; nonrequested presenters cannot upload; upload must complete within the window; private objects cannot be accessed before scanning clears; qualification does not change from upload.
- **English/Arabic:** Participant/non-review administration bilingual; scientific materials English/LTR; spoken-presentation requirements remain unset pending approval.
- **Accessibility:** Keyboard/mobile file selection, announced progress/failure, accessible checklist and clear cutoff/timezone explanation.
- **Security/RLS:** Request/owner/edition checks, private allowlisted files and generated names; administrator status privileges separate from participant uploads.
- **Audit/email:** Audit request/replacement/completion; English authorized request/reminder jobs; no award/certificate email from upload.
- **Automated tests:** Nonqualified/nonrequested upload, expired request, forbidden file, pending/quarantined object access, duplicate completion and preserved replaced version.
- **Manual UAT:** Qualified synthetic presenter receives request, uploads/replaces material and inspects accurate status after scan failure.
- **Release gate:** REL-04 configured 3MT final-material stage and private-file acceptance evidence.
- **Owner type:** Full-stack/security engineer with 3MT lead.
- **TBD blocked:** Live final materials yes, CFG-06; private request/version boundary no.

## BL-TMT-05 — Collect separate 3MT event scorecards under approved rules

- **Source IDs:** TMT-02, ROL-06, ROL-12, REL-05.
- **Status:** Planned; live event scoring closed.
- **Purpose:** Assigned final judges can score qualified presentations without modifying pre-event qualification reviews.
- **Scope:** 3MT-specific event rubric, judge assignments/conflicts, score drafts/submission/amendment until lock, configured aggregation and tie readiness using shared event-score infrastructure.
- **Exclusions:** Assumed external duration/slide/judge rules, invented criteria/scales, award publication, mixing qualification and event score records.
- **Dependencies:** BL-TMT-04; BL-REV-08 shared event-score infrastructure; [DR-CFG-06](DECISION_REQUIRED.md#dr-cfg-06).
- **Roles:** 3MT judging committee; assigned final Faculty Judge; authorized 3MT administrator.
- **States/transitions:** Assigned event score is drafted, submitted and locked under configured cutoff; unresolved conflict/incomplete scores remain incomplete under approved readiness rules.
- **Data touched:** Event assignments, rubric versions, conflicts, independent final scorecards/locks and aggregation provenance.
- **Acceptance criteria:** Missing judge/rubric configuration blocks live scoring; unassigned/conflicted judges cannot score; locked score rejects stale edit; event result cannot overwrite qualification review.
- **English/Arabic:** Assessment UI and scientific content English-only; non-review event administration bilingual.
- **Accessibility:** Phone/keyboard score entry, labelled scales, visible save/lock status, readable error summary and semantic totals.
- **Security/RLS:** Assignment/version/edition/MFA enforced on reads/writes; minimal approved final materials; no general participant or private evidence access.
- **Audit/email:** Audit assignment/conflict/amendment/lock; English judge notices only; no applicant outcome email from score completion.
- **Automated tests:** Conflicted/unassigned access, stale version, lock boundary, missing-score readiness, unauthorized material retrieval and distinct qualification records.
- **Manual UAT:** Two or more judges only as permitted by a labelled synthetic setting; rehearse save failure, conflict reassignment and locking.
- **Release gate:** REL-05 approved 3MT rules/judges/rubric/ties and trained-device rehearsal.
- **Owner type:** 3MT/judging lead with full-stack engineer and QA.
- **TBD blocked:** Live event judging yes, CFG-06; track adapter using synthetic settings no.

## BL-TMT-06 — Release approved 3MT results and certificate evidence

- **Source IDs:** TMT-02, CRT-03, REV-07, REL-05.
- **Status:** Planned; result/certificate gates closed.
- **Purpose:** The authorized competition team can release an outcome supported by the separately approved 3MT evidence rules.
- **Scope:** Approved presentation/award evidence checklist; private result preparation and explicit release using shared publication service; separate role/competition certificate evidence handoff without issuance.
- **Exclusions:** Invented awards/prizes/eligibility, automatic certificates from qualification, research-supervisor winner rule, accredited-credit claims.
- **Dependencies:** BL-TMT-05; approved evidence capture and publication service; [DR-CFG-06](DECISION_REQUIRED.md#dr-cfg-06), [DR-CFG-08](DECISION_REQUIRED.md#dr-cfg-08).
- **Roles:** Authorized 3MT award/result publisher; evidence verifier; certificate administrator with independent release authority.
- **States/transitions:** Prepared result stays private; complete approved evidence plus authorized release produces published outcome; certificate evidence remains pending its distinct eligibility/template/batch release.
- **Data touched:** Evidence references, prepared result/approval, publication snapshot, notification jobs and minimal certificate-evidence handoff.
- **Acceptance criteria:** Missing configured evidence blocks release; result preview matches published snapshot; duplicate request creates one release; result publication alone cannot issue a certificate or rewrite attendance.
- **English/Arabic:** Participant and non-review administration bilingual; scientific outcome material English where applicable; English transactional result emails.
- **Accessibility:** Keyboard preview/confirm, textual missing-evidence explanation, clear published versus pending state and accessible participant fallback.
- **Security/RLS:** Separate result-release permission with MFA; participant sees own published result only; certificate handoff excludes confidential scores/notes.
- **Audit/email:** Audit evidence corrections, approval and publication; deduplicated English result email; certificate email follows the later authorized certificate release only.
- **Automated tests:** Missing evidence, unauthorized publisher, private result leak, duplicate release, stale preview and certificate non-issuance.
- **Manual UAT:** Prepare then release a synthetic result; verify applicant visibility changes once and certificate remains gated.
- **Release gate:** REL-05 approved 3MT result/evidence rules; independent role/competition certificate approval remains required.
- **Owner type:** 3MT/event lead with full-stack/privacy engineer.
- **TBD blocked:** Live results and certificate rules yes, CFG-06/CFG-08; bounded publication/evidence integration no.
