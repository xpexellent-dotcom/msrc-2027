## Migration and contracts

New review-only migration:
`supabase/migrations/20261022120000_staff_registration_complete_history.sql`.
It follows `20261020160000_operational_health.sql`; no previous migration changed.

- Replaces the existing signature
  `public.msrc_staff_registration_detail(edition_key text, request_id uuid)
  returns jsonb`. Authorization remains assured registration/workshop
  administrators or Super Admins through `msrc_staff.authorize`; authenticated
  execution only. READ COMMITTED is checked at entry before any early return.
- Adds `historyVersion: 1` to the RPC envelope. The handler treats an older ready
  RPC without that marker as `area-not-ready`.
- History rows are `{id,event,actorKind,from,to,at,performerName}`. New types are
  `StaffRegistrationEvent` and `StaffRegistrationHistoryRow`; `actorKind` is
  `participant | automatic | staff`. Submission and ticket rows have null
  `from`/`to`. The projection validates event/actor/transition combinations,
  field allowlists, IDs and newest-first timestamps.
- Adds private `msrc_registration.ticket_audit_event() returns trigger`, with
  `SECURITY DEFINER`, empty search path and no client/service execute grant.
  The ticket trigger records the two ticket events atomically; a unique
  request/event index prevents duplicates. Existing ticket facts are backfilled
  using their exact `issued_at`/`revoked_at`, without inventing actors or request
  states, issuing tickets, changing requests or enqueueing messages.
- Preview contract: `email-previews` added to `StaffScreen` and `StaffArea`;
  `StaffEmailPreview` contains template key/version, recipient, subject, text,
  HTML. `StaffResponse.emailPreviews` is optional. The existing staff GET area
  returns these generated strings after Super Admin/TOTP checks, before any
  optional area RPC. No new public RPC is needed for A or D.
