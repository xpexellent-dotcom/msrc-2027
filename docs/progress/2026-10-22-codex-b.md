## Migration and contracts

New review-only migration:
`supabase/migrations/20261022130000_checkin_attendance.sql`, after ACD's
`20261022120000_staff_registration_complete_history.sql`.

Adds `msrc_registration.settings.conference_days date[]`, private forced-RLS
`attendance`, immutable `attendance_audit`, and `checkin_limits` tables. One
attendance row per ticket/day records server time, staff performer, optional
entry label and `scan | manual_code`. Undo retains the row and original audit
snapshots; later re-entry reuses that row. No client table grants are added.

All functions below return `jsonb`:

```sql
public.msrc_staff_checkin(
  edition_key text, ticket_token_or_reference text,
  conference_day date, entry_point text)
public.msrc_staff_checkin_undo(
  edition_key text, attendance_id uuid, reason text)
public.msrc_staff_attendance_summary(edition_key text, day date)
public.msrc_registration_attendance(edition_key text, session_claims jsonb)
```

The first three grant authenticated execution but enforce current edition
roles and native session assurance. Scan/summary allow `checkInStaff` and
`superAdmin`; undo only `superAdmin`. Participant attendance is service-only,
bound to the verified native participant session and existing closed flags.
The existing `msrc_staff_registration_settings_save(text,jsonb,uuid)` adds
validated days without changing completeness or enabling registration.

Scanner outcomes: `checked_in`, `already_checked_in`, `revoked`, `not_found`,
`wrong_day`, `not_approved`. Duplicate success includes original time/performer.
Rate, authorization and infrastructure failures remain separate. Ticket secret
hash comparison follows ENG-054; ambiguous manual references fail closed.
Settings/request/ticket locks serialize admission and concurrent revocation.
Attendee authority locks use NOWAIT to avoid cross-account lock cycles; their
contention returns retryable `unavailable`. Staff assurance is rechecked after
waits. READ COMMITTED guards run at function entry.

The engineering abuse limit is 120 scan/undo attempts per native staff session
per 60 seconds. Audit snapshots exclude raw tokens, submitted unknown references,
identity documents and participant contact data. Counts disclose only totals
and method subtotals. Null summary day fetches configuration with zero counts.

HTTP/type additions:

- `check-in` StaffScreen/StaffArea; `check-in` and `check-in-undo` actions.
- `checkIn: {conferenceDays, summary: {day, checkedIn, scan, manualCode} | null}`.
- `checkInResult: {status, attendanceId?, checkedInAt?, performedBy?}`; successful
  and duplicate outcomes project only the required provenance.
- Settings `conference_days: string[] | null`, sorted unique real dates with a
  31-day engineering input bound; audit value types include string arrays.
- Participant ready state `attendance: {conferenceDay, checkedInAt}[]`.
